# Sana Hub — AI Sana Challenge Hub

Минимальный MVP для трека HackAlem / AI Sana: от короткой бизнес-задачи к понятной карточке, каталогу и ручному выбору команды.

## Стек и архитектура

Изначально в репозитории не было frontend/backend стека, поэтому выбран SPA на vanilla JavaScript и ES-модулях с минимальным Node.js backend без внешних зависимостей. Браузер вызывает `POST /api/ai/analyze`, backend вызывает OpenAI Responses API и валидирует Structured Output. Ключ и модель никогда не отправляются в браузер. Данные демо хранятся в `localStorage`; fallback находится в `src/services/ai.js`, server-only OpenAI service — в `src/services/ai-server.mjs`, scoring — в `src/services/scoring.js`.

## Запуск

Установите переменные окружения на backend. Начните с `.env.example`; реальный `.env` не добавляйте в Git:

```powershell
$env:OPENAI_API_KEY="your-key"
$env:OPENAI_MODEL="your-model-id"
```

Запустите Node.js web-сервер:

```bash
node server.mjs
```

Откройте `http://localhost:4173`. При отсутствии `OPENAI_API_KEY` или `OPENAI_MODEL`, timeout, ошибке API или неправильном JSON приложение переключается на mock fallback с тем же контрактом.

## Страницы

- `#/home` — landing с выбором роли;
- `#/onboarding/business` — простой профиль представителя бизнеса;
- `#/onboarding/student` — профиль студента, фрилансера или команды;
- `#/business/dashboard` — задачи и предложения бизнеса;
- `#/business/intake` — описание и AI-уточнение;
- `#/business/card` — редактируемая карточка, score breakdown, публикация;
- `#/catalog` — общий marketplace-каталог с поиском, фильтрами по теме и уровню и сортировкой по рейтингу;
- `#/task/:id` — полная карточка задачи и форма предложения с автоматически подставленным профилем команды;
- `#/business/proposals` — ручное принятие или отклонение предложений.
- `#/profile` — сохранённый demo-профиль текущей роли.

Переключатель «Бизнес / Команда» заменяет авторизацию в демонстрационном сценарии.

## Модели и scoring

`Task` содержит title, context, need, users, data, constraints, expectedResult, successCriteria, businessContact, interactionFormat, score, readinessLevel и status. `Team` содержит название, интересы, навыки и технологии. `Proposal` связывает задачу и команду и хранит solutionIdea, plan, duration, prototypeUrl и статус `pending | accepted | rejected`.

Score считается только детерминированной логикой приложения: контекст + потребность — 20; данные — 20; ожидаемый результат — 15; критерии успеха — 15; ограничения — 10; пользователи — 10; связь с бизнесом — 10. Уровни: `0–39 Черновик`, `40–69 Рабочая`, `70–89 Готовая`, `90–100 Приоритетная`. Пустые значения и маркеры «Требуется уточнение» не получают баллы. До подтверждения редактор показывает только прогноз; официальный score рассчитывается по подтверждённым данным. На экране видны breakdown, потенциальный прирост и конкретные рекомендации.

При настроенном `OPENAI_API_KEY` AI получает исходное описание, текущую карточку, обязательные поля, предыдущие вопросы и ответы пользователя. Результат запрашивается через Structured Outputs JSON Schema и проходит backend-валидацию. `OPENAI_MODEL` задаёт модель без изменения основной логики. Локальный fallback динамически выбирает вопросы по незаполненным полям, задаёт минимум 3 вопроса, оставляет результат редактируемым и не подставляет неподтверждённые факты. Публикация требует ручного подтверждения бизнеса; команда никогда не назначается автоматически.

## Демо-данные и сценарий

В `src/data.js` есть 5 синтетических задач, 5 команд и 5 предложений. Для демонстрации: введите слабое описание в режиме бизнеса, покажите вопросы, ответьте на них прямо в форме, сформируйте карточку, отредактируйте поля, подтвердите и опубликуйте её. Переключитесь в режим команды, найдите задачу через каталог, отправьте предложение с автоматически подставленным профилем, затем вернитесь в режим бизнеса и примите или отклоните его вручную. Количество откликов не ограничено, низкий рейтинг не скрывает опубликованную задачу, автоматического назначения команды нет.

Для сброса демо-данных выполните в консоли браузера `resetSanaDemo()`.

## Стабильность MVP

Незавершённый AI/card workflow сохраняется локально и восстанавливается после обновления `#/business/intake` и `#/business/card`. Persisted-данные валидируются и нормализуются при загрузке: некорректные сущности и orphan proposals не приводят к blank page, score опубликованных карточек пересчитывается детерминированно. Proposal защищён от двойной отправки, а статусы меняются только ручным действием бизнеса. Backend возвращает явные ответы для 400, 404, 405 и безопасно обрабатывает ошибки OpenAI, timeout, network failure и malformed schema через fallback.

## Проверки

Проект использует встроенный Node.js test runner и не требует npm-зависимостей:

```bash
node --test
```

Тесты покрывают динамические вопросы, повторно известные данные, запрет выдумывания, schema validation, OpenAI-ошибки, точные границы readiness-уровней, score growth, максимум 100, неподтверждённые поля, пересчёт после редактирования и видимость низкоскоринговой опубликованной задачи.
